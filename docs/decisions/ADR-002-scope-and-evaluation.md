# ADR-002: 機能範囲と評価の枠組み

- ステータス: 採用
- 決定日: 2026-11-01(評価方式は2026-11-02に変更)

## 背景

SOC・CSIRTの機能範囲と、その機能水準をどう評価するかを決める必要がある。

## 決定

- SOC・CSIRTの機能範囲は、Exabeam社の解説記事
  [SOCとCSIRT:6つの主な違いと両方が必要な組織とは?](https://www.exabeam.com/ja/explainers/information-security/soc-vs-csirt-6-key-differences-and-which-organizations-need-both/)
  の定義に基づく。
  - SOC: 常時の監視・検知・分析、インシデント・イベントの管理、コンプライアンスの監視と報告
  - CSIRT: インシデント対応の統制・調整、再発防止のための助言
- 評価はNIST CSF 2.0を使い、カテゴリ単位のプロファイル(Current / Target)と、組織全体のTierで行う。
- CSF 2.0との対応関係は [REC-004](../../05-records-kpi/05-04-nist-csf-profile.md) の1箇所にだけ記載する。

## 理由

- Exabeamの定義は、SOCとCSIRTの違いを機能・責任・体制・活動の周期・連携範囲で整理しており、両者の役割分担を決める土台になる。
- NIST CSF 2.0のTierは本来、組織全体のリスクのガバナンスと管理を表すもので、機能やカテゴリごとの成熟度を表すものではない。
  カテゴリごとの評価はプロファイルで行うのがNISTの想定に合う。
- 対応表を各文書に持たせると、文書の改訂で内容がずれる(初版では実際にずれが生じた)。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| 機能ごとにTierを付ける(初版の方式) | NIST CSF 2.0のTierの定義と合わない |
| 独自の5段階成熟度(CMMI風) | 他組織と比べにくい。ただしプロファイルの記入値には独自の5段階の目安を使っている |
| 各文書の末尾にCSF対応表を置く(初版の方式) | 内容が重複し、ずれる |

## 変更するときの影響範囲

- 機能範囲を広げる場合(例: Protectを対象に含める): [OV-002](../../00-overview/00-02-nist-csf-usage.md) の対象範囲、[REC-004](../../05-records-kpi/05-04-nist-csf-profile.md) の範囲欄
- 別の評価枠組み(ISO/IEC 27001など)を併用する場合: REC-004と同じ形式で対応表を別文書として追加する
