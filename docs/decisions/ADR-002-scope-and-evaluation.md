# ADR-002: 機能範囲と評価の枠組み

- ステータス: 採用
- 決定日: 2026-11-01(評価方式は2026-11-02、機能範囲の根拠は2026-11-03に変更)

## 背景

SOC・CSIRTの機能範囲と、その機能水準をどう評価するかを決める必要がある。

## 決定

- SOC・CSIRTの機能範囲は、[NIST SP 800-61 Rev.3](https://doi.org/10.6028/NIST.SP.800-61r3) のインシデント対応モデルに基づき、CSF 2.0の機能で定義する。
  - SOC: 継続的な監視・検知・分析(Detect)、一次評価と初期対応(Respond)、コンプライアンスの監視と報告(Govern)
  - CSIRT: 重大インシデントの対応の統制・調整と報告(Respond)、復旧の統制(Recover)、再発防止(Identify の ID.IM)
  - 機能とSOC・CSIRTの分担の詳細は [OV-002](../../00-overview/00-02-nist-csf-usage.md) 第1章
- 評価はNIST CSF 2.0を使い、カテゴリ単位のプロファイル(Current / Target)と、組織全体のTierで行う。
- CSF 2.0との対応関係は [REC-004](../../05-records-kpi/05-04-nist-csf-profile.md) の1箇所にだけ記載する。

## 理由

- SP 800-61 Rev.3は、インシデント対応をCSF 2.0の機能で整理している。機能範囲の定義と評価(CSF 2.0のプロファイル)を同じ枠組みで行えるため、
  定義と評価の間にずれが生じない。
- 設計根拠をNISTの文書に統一する方針([OV-005](../../00-overview/00-05-references.md))に合わせる。
  なお、SP 800-61 Rev.3はSOCとCSIRTの組織上の区分を定めていないため、区分は本一式の設計判断とする([ADR-003](ADR-003-soc-csirt-structure.md))。
- NIST CSF 2.0のTierは本来、組織全体のリスクのガバナンスと管理を表すもので、機能やカテゴリごとの成熟度を表すものではない。
  カテゴリごとの評価はプロファイルで行うのがNISTの想定に合う。
- 対応表を各文書に持たせると、文書の改訂で内容がずれる(初版では実際にずれが生じた)。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| 機能範囲を特定のベンダーの解説記事の定義に基づかせる(初版の方式) | 設計根拠をNISTの文書に統一する方針に合わない。評価の枠組み(CSF 2.0)とも別の整理になる |
| 機能ごとにTierを付ける(初版の方式) | NIST CSF 2.0のTierの定義と合わない |
| 独自の5段階成熟度(CMMI風) | 他組織と比べにくい。ただしプロファイルの記入値には独自の5段階の目安を使っている |
| 各文書の末尾にCSF対応表を置く(初版の方式) | 内容が重複し、ずれる |

## 変更するときの影響範囲

- 機能範囲を広げる場合(例: Protectを対象に含める): [OV-002](../../00-overview/00-02-nist-csf-usage.md) の対象範囲、[REC-004](../../05-records-kpi/05-04-nist-csf-profile.md) の範囲欄
- 別の評価枠組み(ISO/IEC 27001など)を併用する場合: REC-004と同じ形式で対応表を別文書として追加する
