# ADR-008: AIの権限は3段階、Tier1はAI出力の監督者

- ステータス: 採用(Lv1・Lv2の条件に「根拠が検証済み」を [ADR-013](ADR-013-evidence-grounded-investigation.md) で追加)
- 決定日: 2026-11-02

## 背景

AIにどこまで自動で措置を任せるか、AI導入後に人間のTier1が何を担うかを決める必要がある。

## 決定

- 措置を Lv1(自動実行)、Lv2(自動実行後に人間が確認)、Lv3(事前承認)の3段階に分ける。
- 区分は、可逆性、対象数(Lv1は1、Lv2は10まで `P-09` `P-10`)、保護資産の有無で決める。
- 外部への報告、データの削除、人事上の措置などは、権限レベルにかかわらずAIは実行しない。
- Tier1の役割を、一次評価の実施者から、AIの判定と措置を監督する人に置き換える。
- 全自動実行を止めるKill-switchを設ける。

詳細は [AI-002](../../02-agentic-ai/02-02-authority-levels.md)、[AI-004](../../02-agentic-ai/02-04-audit-and-kill-switch.md)。

## 理由

- 可逆的で影響の小さい封じ込めをAIに任せると、夜間・休日でも初動が速くなる。
- 対象数の上限と保護資産の除外により、誤判定や攻撃による大規模な誤隔離を防ぐ。
- 初版では「単一対象ならLv1」だけで判断していたため、基幹サーバーも自動で隔離される可能性があった。
- 一次評価をAIが担う以上、Tier1が同じ評価を手作業で繰り返すのは重複である。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| 読み取り系のみ自動、措置はすべて人間の承認 | 夜間・休日の初動が遅れる |
| 既知のパターンの措置はすべて自動 | 誤作動したときの影響が大きい |
| 2段階(自動 / 事前承認) | 複数対象への可逆的な措置まで事前承認になり、遅れる |
| Lv2の上限を50対象にする | 誤作動したときの影響が大きい。導入後の実績を見て広げる |
| Tier1は従来どおり一次評価を行い、AIは補助 | 導入初期の保守的な運用としては有効。その場合は [GOV-001](../../01-governance/01-01-organization-structure.md) 第2章と各Runbookの手順1を変更する |

## 変更するときの影響範囲

- 対象数の上限を変える場合: [OV-004](../../00-overview/00-04-customization-points.md) の `P-09` `P-10`
- 区分の数を変える場合: [AI-002](../../02-agentic-ai/02-02-authority-levels.md)、[GOV-004](../../01-governance/01-04-raci.md)、[GOV-005](../../01-governance/01-05-operating-hours.md)、[REC-002](../../05-records-kpi/05-02-ai-decision-log-format.md)、各Runbookの対応手順
