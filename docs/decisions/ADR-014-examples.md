# ADR-014: 利用事例の置き場所と扱い

- ステータス: 採用
- 決定日: 2026-11-08

## 背景

汎用の一式は製品に依存しない形で書いている([OV-003](../../00-overview/00-03-document-conventions.md) 第4章)。利用者が自組織に当てはめる
手順を具体的に示すため、架空の組織と具体的な製品に当てはめた利用事例を加えたい。

## 決定

- 利用事例は、同じリポジトリの `examples/<slug>/` に置く。
- 事例は汎用の一式の文書を書き換えない。汎用の文書の規則を、事例の組織と製品でどう実現するか(差分)だけを書く。
- 事例の文書では製品名を書いてよい。製品の情報には確認日を付ける。
- 事例は汎用の一式の設計根拠にしない([OV-005](../../00-overview/00-05-references.md) 第1章「特定の製品・サービス・企業の事例は根拠にしない」)。

## 理由

- 事例が汎用の文書を参照するだけなら、汎用の文書を改訂したときに事例との不整合を同じ変更の中で直せる。
- 差分だけを書くことで、汎用の一式のどこが組織ごとに変わるのかが読み手に分かる。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| フォーク | 自分のリポジトリは同じアカウントにフォークできない。公開リポジトリのフォークは非公開にできない |
| 履歴ごと複製した別リポジトリ | 汎用の一式を丸ごと書き換える場合に向く。差分だけを書く事例では、リポジトリを分ける利点が小さい。事例を非公開で作り込む必要が生じた場合は、この案に切り替える |
| 同じリポジトリの長期のブランチ | ブランチは本流に合流する作業のためのもので、並行して持ち続けると利用者が混乱する |
| 汎用の文書に製品別の付録を加える | 汎用の文書が特定の製品に依存し、[OV-003](../../00-overview/00-03-document-conventions.md) 第4章の規約に反する |

## 変更するときの影響範囲

- 汎用の文書の文書ID・パラメータ・章番号を変える場合: `examples/` 配下で参照している箇所
- 事例を別リポジトリに移す場合: `examples/README.md`、README、[OV-003](../../00-overview/00-03-document-conventions.md) 第1章
