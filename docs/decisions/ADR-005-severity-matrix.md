# ADR-005: 重大度は影響度×緊急度のマトリクス

- ステータス: 採用
- 決定日: 2026-11-01(4段階)、2026-11-02(マトリクス方式に変更)

## 背景

初版では、重大度を「影響を受けた構成会社の数」を中心にした文章で定義し、各Runbookでもシナリオごとに
重大度を定め直していた。そのため、Runbookと全体の定義が食い違っていた。

## 決定

- 重大度はCritical / High / Medium / Lowの4段階とする。
- 影響度(大/中/小)と緊急度(高/中/低)のマトリクスで決める。
- Critical・HighでCSIRTを発動する。
- 定義は [GOV-002](../../01-governance/01-02-severity-matrix.md) にだけ置き、Runbookは下限を引き上げる補正だけを書く。

## 理由

- 構成会社の数は規模の差が大きく、影響の大きさを正しく表さない。業務と情報への影響で判断する方が実態に合う。
- 定義を1箇所に置くと、見直したときに全Runbookに一度に反映される。
- 4段階は一般的で、Critical・HighでCSIRTを発動するという基準を作りやすい。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| 5段階(SEV1〜SEV5) | 段階が細かく、判定がぶれやすい |
| 3段階(高・中・低) | 1万人・100社の規模では区別が粗い |
| 文章による定義を精緻にする | Runbookごとの定義の重複は解消しない |

## 変更するときの影響範囲

- 段階の数やマトリクスを変える場合: [GOV-002](../../01-governance/01-02-severity-matrix.md)、[GOV-005](../../01-governance/01-05-operating-hours.md)、[REC-001](../../05-records-kpi/05-01-incident-record-format.md)、[REC-003](../../05-records-kpi/05-03-kpi-sheet.md)、各Runbookの「重大度の補正」
- 初動対応時間目標だけを変える場合: [OV-004](../../00-overview/00-04-customization-points.md) の `P-04`〜`P-07`
