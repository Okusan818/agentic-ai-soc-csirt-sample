# ADR-003: SOCは常設、CSIRTは兼務・発動型

- ステータス: 採用
- 決定日: 2026-11-01

## 背景

グループ専任のシステム子会社が、SOCとCSIRTの両方の機能を担う。両者をどう組織するかを決める必要がある。

## 決定

- SOCはシステム子会社内の常設チームとし、Tier1/2/3で構成する。
- CSIRTは専任チームを置かず、平時はTier2/3が兼務する。Critical・Highの事案で発動し、
  インシデントマネージャー・フォレンジックアナリスト・復旧スペシャリストの体制を組む。
- 発動時の役割は上記の3つとし、広報・法務の連絡役や記録係は置かない(インシデントマネージャーが兼ねる)。

詳細は [GOV-001](../../01-governance/01-01-organization-structure.md)。

## 理由

- NIST SP 800-61 Rev.3 第2.2節は、インシデント対応がかつては組織内のインシデント対応チームでほぼ完結していたのに対し、
  現在は社内外の多くの関係者の参加に依存するとしている。インシデントハンドラーは、社内の要員のほか、
  契約先(例: SOCのMSSPへの委託)や、必要なときに支援を受ける先(例: 親組織)でもよいとしている。
  インシデント対応の機能を常設の専任チームで持つことは必須ではない。
- 同節は、大規模な組織が複数のインシデント対応チームを持つ場合、手順・訓練をそろえ情報を共有するため、
  単一の調整された組織体(フェデレーション)とすべきとしている。グループ専任のシステム子会社に
  SOC・CSIRTを集約する本一式の構成は、この考え方に沿う([ADR-004](ADR-004-group-companies.md))。
- 専任のCSIRTを置くと、事案のない時期の人員が遊休になる。兼務にすると、平時のSOC業務で得た知見を発動時にそのまま使える。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| SOCとCSIRTを別の専任チームにする | 人員が多く必要になる |
| 同一チームで機能を区別しない | 平時と発動時の役割・権限が混ざる |
| 発動時の役割に広報・法務の連絡役と記録係を加える | 今回のサンプルでは採用しなかった。大規模な事案が多い組織では追加を検討する |

## 変更するときの影響範囲

- CSIRTを専任チームにする場合: [GOV-001](../../01-governance/01-01-organization-structure.md) 第3章、[GOV-004](../../01-governance/01-04-raci.md)、[CSIRT-001](../../04-csirt-playbooks/04-01-incident-response-lifecycle.md)
- 発動時の役割を追加する場合: GOV-001 第3章の表、GOV-004 第2章の列
