# ADR-011: CSIRTは共通ライフサイクルとシナリオ別の補足

- ステータス: 採用
- 決定日: 2026-11-02

## 背景

CSIRTの手順書を、シナリオ別に作るか、共通の手順として作るかを決める必要がある。

## 決定

- すべての事案に共通するライフサイクル(準備、検知・分析、封じ込め、根絶、復旧、事後活動)を1つ作る([CSIRT-001](../../04-csirt-playbooks/04-01-incident-response-lifecycle.md))。
- 外部関係者との連携と事後レビューを、共通の手順として別に作る。
- ランサムウェアと情報漏洩は、固有の判断が多いため補足Playbookを作る。補足Playbookは共通の手順を繰り返さず、固有の判断だけを書く。

## 理由

- CSIRTの作業は、シナリオによらず共通の部分が大きい。共通部分を1つにまとめると、改訂の手間が減る。
- ランサムウェア(バックアップの判断、身代金の方針)と情報漏洩(報告期限、本人への通知)は、共通の手順だけでは判断できない点が多い。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| シナリオ別にすべて作る | 共通部分が重複する |
| 共通ライフサイクルのみ | 重大シナリオの固有の判断が抜ける |
| 指揮体制(ICS)を明記する | 今回のサンプルでは採用しなかった |

## 変更するときの影響範囲

- 補足Playbookを追加する場合: [CSIRT-000](../../04-csirt-playbooks/04-00-playbook-template.md) を複製し、[OV-003](../../00-overview/00-03-document-conventions.md) 第6章の手順に従う
