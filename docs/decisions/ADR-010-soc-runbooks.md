# ADR-010: SOC手順は7シナリオと定常業務、共通の雛形

- ステータス: 採用
- 決定日: 2026-11-02

## 背景

SOCの手順書として、どのシナリオを用意し、どういう構成で書くかを決める必要がある。

## 決定

- 検知シナリオ別のRunbookを7件用意する(異常ログイン、フィッシング、マルウェア、ランサムウェアの前兆、
  内部不正、権限昇格、クラウドの公開設定ミス)。
- シナリオに依存しない定常業務(日常運用、脅威ハンティング、コンプライアンス監視)を別の番号帯で用意する。
- Runbookは共通の雛形([SOC-000](../../03-soc-runbooks/03-00-runbook-template.md))に従い、手順ごとに
  実行主体(AI・Tier)と権限レベルを1つの表に書く。
- 製品固有のクエリは書かず、参照するログ・アラートの種類で書く。

## 理由

- 7シナリオは、オンプレミスとクラウドの両方で頻度が高く、AIの自動措置と人間の承認の分け方を示しやすい。
- SOCの機能には、継続的な監視(CSF 2.0 DE.CM)とコンプライアンスの監視(GV.OC、GV.OV)が含まれる([ADR-002](ADR-002-scope-and-evaluation.md))。シナリオ別の手順だけでは表せない。
- 実行主体と権限レベルを同じ表に書くと、AIと人間の分担が手順ごとに分かる。初版ではTier別の作業とAIの分担を別の表にしていたため、誰が一次評価をするのかが不明確だった。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| 4シナリオ | サンプルとしての網羅性が低い |
| 2シナリオ | 同上 |
| SIEMのクエリ例を含める | 特定の製品に依存する |

## 変更するときの影響範囲

- シナリオを追加する場合: [SOC-000](../../03-soc-runbooks/03-00-runbook-template.md) を複製し、[OV-003](../../00-overview/00-03-document-conventions.md) 第6章の手順に従う
- 雛形の構成を変える場合: 全Runbook
