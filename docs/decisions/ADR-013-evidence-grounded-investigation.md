# ADR-013: 証拠の収集と推論を分け、所見を証拠に基づかせる

- ステータス: 採用
- 決定日: 2026-11-03

## 背景

[ADR-007](ADR-007-agent-architecture.md) では、調査・分析エージェントがログ検索・脅威インテリジェンスの照会を
自ら行う構成としていた。この構成では、次の問題が起こりうる。

- 証拠に裏付けられない主張が、そのまま判定や措置の根拠になる。NIST AI 600-1(`N-04`)は、生成AIが誤った内容を
  もっともらしく出力するリスクを「作話(Confabulation)」として挙げている。
- 調査対象のデータ(メール本文、ログ中の文字列)に仕込まれた指示により、エージェントが対象外の構成会社・期間・ログを
  参照する。NIST AI 100-2 E2025(`N-05`)は、外部から取り込むデータを通じた間接プロンプトインジェクションを分類している。
- ログが取得できなかったことと、調べて該当がなかったことが区別されない。
- AIの出力を人間が過度に信頼する(自動化バイアス)。NIST AI 600-1は、これを「人間とAIの構成(Human-AI Configuration)」のリスクとして挙げている。
- 判定の根拠を後から検証できない。NIST AI RMF(`N-03`)は、信頼できるAIの特性として「妥当性と信頼性」「説明責任と透明性」
  「説明可能性」を挙げている。

参照文献の一覧は [OV-005](../../00-overview/00-05-references.md) を参照。

## 決定

- 調査を「軽量トリアージ → 証拠収集(コード)→ 専門エージェントの並列分析 → 統合 → 引用検証(コード)→ 人間の判断」の流れとする。
- 調査・分析エージェントを、4つの専門エージェント(テレメトリ分析、資産・ユーザーコンテキスト、
  グループ横断テレメトリ、脅威インテリジェンス)と統合エージェントからなる群に分ける。
  グループ横断テレメトリは、構成会社間では集約値だけを扱う。
- 判定区分と推奨を閉じた語彙とし、「判定保留(証拠不足)」を設ける。
- カバレッジギャップ(未確認)を「確認済み・該当なし」と区別して記録する。
- 各Runbookに、収集する証拠と、措置に必要な証拠を定義する(第7章)。
- AIによるLv1・Lv2の措置は、根拠が検証済みの場合に限る。検証済みでない場合はLv3として承認者に判断を求める。

詳細は [AI-006](../../02-agentic-ai/02-06-evidence-grounded-investigation.md)、[AI-001](../../02-agentic-ai/02-01-architecture.md)、
[AI-002](../../02-agentic-ai/02-02-authority-levels.md) 第2章。

## 理由

| 決定 | 対処するリスク | 根拠([OV-005](../../00-overview/00-05-references.md)) |
|---|---|---|
| 所見の引用をコードで検証し、裏付けのない所見を除去する | 作話による誤った判定・措置 | `N-04` 作話、`N-03` 妥当性と信頼性 |
| 証拠の収集をコードで行い、調査範囲を強制する | 間接プロンプトインジェクションによる範囲の逸脱 | `N-05`、`N-06` AC-4(情報フローの制御)、SI-10(入力の検証) |
| 構成会社間は集約値だけを扱う | 別法人の個別データの越境 | `N-04` データプライバシー、`N-06` AC-4 |
| 判定保留を設け、カバレッジギャップを明示する | 不十分な証拠での推測と、それへの過信 | `N-04` Human-AI Configuration、`N-03` 説明可能性 |
| 証拠パッケージと検証結果を判断ログに残す | 判定の根拠を後から検証できない | `N-03` 説明責任と透明性、`N-06` AU-3、AU-9 |
| Lv1・Lv2の自動実行を、根拠が検証済みの場合に限る | 検証されていない判定に基づく自動措置 | `N-03` MANAGE、`N-06` AC-6 |

- このほか、「未確認」を明示することで、ログの途絶や未接続のログソースを検知の改善([SOC-053](../../03-soc-runbooks/03-53-compliance-monitoring.md))につなげられる。
- Tier1のレビューが「AIの分析のやり直し」から「引用とギャップの確認」になり、監督の負荷が下がる。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| 現状維持(エージェントが自ら検索する) | 作話と範囲の逸脱を、構造的に防げない |
| AIは推奨のみとし、措置はすべて人間が実行する | 夜間・休日の初動が遅れる([ADR-008](ADR-008-ai-authority-levels.md)、[ADR-009](ADR-009-operating-hours.md))。ただし、導入初期の保守的な運用としては有効であり、その場合は [AI-002](../../02-agentic-ai/02-02-authority-levels.md) のLv1・Lv2を使わない |
| 引用の検証をモデル(別のエージェント)に行わせる | 検証自体が誤る・攻撃される可能性がある。存在・範囲・値の一致はコードで確認できる |
| 判定信頼度の閾値で措置の可否を決める | 信頼度は根拠の有無を示さない。高い信頼度で誤った主張をすることがある |

## 変更するときの影響範囲

- 専門エージェントの分割を変える場合: [AI-001](../../02-agentic-ai/02-01-architecture.md) の表、[AI-006](../../02-agentic-ai/02-06-evidence-grounded-investigation.md) 第5章
- 判定語彙を変える場合: [AI-006](../../02-agentic-ai/02-06-evidence-grounded-investigation.md) 第6章、[REC-001](../../05-records-kpi/05-01-incident-record-format.md)、[REC-002](../../05-records-kpi/05-02-ai-decision-log-format.md)。変更管理([AI-005](../../02-agentic-ai/02-05-ai-specific-threats.md))に従う
- 措置の自動実行に「根拠が検証済み」を求めない場合: [AI-002](../../02-agentic-ai/02-02-authority-levels.md) 第1章・第2章、[SOC-000](../../03-soc-runbooks/03-00-runbook-template.md) の書き方のルール
- 構成会社間で個別データを共有できる契約・規程がある場合: [AI-006](../../02-agentic-ai/02-06-evidence-grounded-investigation.md) 第5章、`P-29`
- NIST IR 8596(Cyber AI Profile)・COSAiSのエージェント向けオーバーレイが確定・公開された場合: [OV-005](../../00-overview/00-05-references.md) 第4章の手順で照合する
