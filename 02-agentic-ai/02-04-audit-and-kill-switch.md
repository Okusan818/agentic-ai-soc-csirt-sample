# AIの監査と緊急停止

## 1. 監査

| 監査 | 実施者 | 頻度 | 内容 |
|---|---|---|---|
| 日次サンプリングレビュー | Tier1 | 毎営業日 | 前日のLv1実行のうち10%(最低10件) `P-13` と、軽量トリアージで誤検知としてクローズした件のうち10%(最低10件) `P-28` を抽出し、判定が妥当だったかを確認する。夜間・休日分は翌営業日に確認する |
| 異常検知アラート | オーケストレーター(自動)→ Tier1 | 常時 | 異常なパターンを検知したら、サンプリングを待たずに人間を呼び出す |
| 定期レビュー | SOCマネージャー | 四半期 `P-16` | 判定の妥当率、取り消し件数、異常検知の件数を集計し、権限レベルの規則と保護資産リストを見直す |

### 異常検知の条件(例)

- 同じ対象への措置を短時間に繰り返している
- 判定信頼度が閾値を下回っている
- 過去に「要修正」と判定されたパターンに似ている
- 短時間に措置の件数が急増している(誤判定の連鎖や、AIへの攻撃の兆候)
- 引用検証で、調査範囲外の項目を引用した所見が見つかった(調査範囲の逸脱、プロンプトインジェクションの兆候)
- 引用検証の不合格率・判定保留率が短時間に急増している(ログの途絶、モデルの挙動の変化の兆候)

> **カスタマイズ:** 閾値は、導入初期の判断ログを基に設定し、定期レビューで調整すること。

### サンプリングレビューの観点

AIの分析を最初からやり直すのではなく、証拠との対応を確認する([AI-006](02-06-evidence-grounded-investigation.md) 第8章)。

| 観点 | 「要修正」とする例 |
|---|---|
| 引用の妥当性 | 引用した証拠項目が、所見の内容を支えていない |
| カバレッジギャップ | 判定に必要な証拠が「未確認」なのに、判定保留にしていない |
| 判定区分 | 証拠から見て、別の判定区分が妥当である |
| 措置 | 措置が仮説に対して過大・過小である |

### 定期レビューの集計元

定期レビューで使う値は、判断ログ([REC-002](../05-records-kpi/05-02-ai-decision-log-format.md))から集計する。
KPIシート([REC-003](../05-records-kpi/05-03-kpi-sheet.md))の対象外とする。

| 集計値 | 算出方法 |
|---|---|
| 判定の妥当率 | レビュー結果が「妥当」の件数 ÷ レビュー件数 |
| 取り消し件数 | 実行結果が「取り消し」の件数(権限レベル別) |
| 異常検知の件数 | 異常検知アラートの件数と、そのうち実際に誤判定だった件数 |
| 引用検証の不合格率 | 除去・訂正された所見の件数 ÷ 所見の総数(エージェント別) |
| 判定保留率 | 判定区分が「判定保留」のケースの件数 ÷ ケースの総数(Runbook別) |
| 未確認の発生件数 | カバレッジギャップの「未確認」の件数(理由別・ログソース別)。ログソースの接続・保存期間の見直しに使う([SOC-053](../03-soc-runbooks/03-53-compliance-monitoring.md)) |
| 軽量トリアージの見逃し | サンプリングで「調査が必要だった」とされた件数 |

## 2. 緊急停止(Kill-switch)

AIの誤判定の連鎖や、AIへの攻撃が疑われる場合に、自動実行をすべて止める。

| 項目 | 内容 |
|---|---|
| 発動できる人 | SOCマネージャー以上(夜間・休日はオンコール三次。[GOV-005](../01-governance/01-05-operating-hours.md)) |
| 発動後の動き | Lv1・Lv2の自動実行を止め、すべての措置をLv3(事前承認)として扱う。一次評価・調査など読み取り系の処理は続ける |
| 解除の条件 | 原因の解消をSOCマネージャーが確認し、セキュリティ運用責任者に報告したうえで解除する |
| 記録 | 発動・解除の日時、発動者、理由を判断ログに記録する |

AIの誤動作によって業務に影響が出た場合は、それ自体をインシデントとして扱う。重大度を
[GOV-002](../01-governance/01-02-severity-matrix.md) で判定し、[CSIRT-001](../04-csirt-playbooks/04-01-incident-response-lifecycle.md) に従って対応する。
