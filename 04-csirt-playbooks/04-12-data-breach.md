# 補足Playbook: 情報漏洩

[CSIRT-001](04-01-incident-response-lifecycle.md) に、情報漏洩に固有の判断を補足する。

## 1. 発動の起点

- [SOC-002 フィッシング](../03-soc-runbooks/03-02-phishing.md)、[SOC-005 内部不正](../03-soc-runbooks/03-05-insider-threat.md)、
  [SOC-007 クラウドの公開設定ミス](../03-soc-runbooks/03-07-cloud-misconfiguration.md) などで、情報の漏洩またはそのおそれが確認された時点
- [CSIRT-011 ランサムウェア](04-11-ransomware.md) でデータの持ち出しが疑われる時点

## 2. フェーズ別の補足

| フェーズ | 固有の判断・作業 |
|---|---|
| 検知・分析 | 漏洩した(おそれがある)データの種類、件数、本人の範囲を特定する。アクセスログから「閲覧された」のか「持ち出された」のかを区別する |
| 封じ込め | 漏洩の経路(公開設定、漏洩した認証情報、内部の人物)に応じて経路を閉じる |
| 根絶 | 漏洩した認証情報の無効化、公開設定の再発防止の設定ルールを適用する |
| 復旧 | 漏洩したデータが悪用されていないかを、可能な範囲で継続して確認する |

## 3. 外部連携・報告の補足

- 報告の主体は、漏洩したデータを取り扱っていた構成会社とする。複数の構成会社のデータが漏洩した場合は、
  それぞれの会社が報告し、グループCISOが内容と時期をそろえる([GOV-003](../01-governance/01-03-external-reporting-flow.md))。
- 個人情報保護法の報告期限(速報・確報)があるため、件数などが確定する前でも判定を始める。
- 本人への通知文は、法務・広報部門と連携して作る。

## 4. 記録

[REC-001](../05-records-kpi/05-01-incident-record-format.md) の共通項目に加えて、次を記録する。

- 漏洩したデータの種類・件数・本人の範囲、漏洩の経路
- 閲覧か持ち出しかの判断と、その根拠
- 本人への通知の日時と方法
