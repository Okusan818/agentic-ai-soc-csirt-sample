# 補足Playbook: ランサムウェア

[CSIRT-001](04-01-incident-response-lifecycle.md) に、ランサムウェアに固有の判断を補足する。

## 1. 発動の起点

- [SOC-004 ランサムウェアの前兆](../03-soc-runbooks/03-04-ransomware-precursor.md) で誤検知でないと判断された時点
- [SOC-003 マルウェア](../03-soc-runbooks/03-03-malware-detection.md) で暗号化・破壊の挙動が確認された時点

## 2. フェーズ別の補足

| フェーズ | 固有の判断・作業 |
|---|---|
| 検知・分析 | 暗号化の進み具合と、バックアップが被害を受けていないかを最優先で確認する。身代金を要求するメッセージがあれば保全し、攻撃グループを特定する |
| 封じ込め | 拡大が速いため、Lv3措置(ファイルサーバーの停止、セグメントの遮断)の承認者を常に呼び出せる状態にしておく。データを持ち出された可能性も調べる(二重恐喝) |
| 根絶 | 攻撃者が使った遠隔操作ツール・追加アカウントを取り除く。認証基盤が侵害された場合は、全特権アカウントの認証情報を変更する |
| 復旧 | バックアップからの復元を第一の選択肢とする。復元の前に、バックアップが感染していないことを確認する |

### 身代金の扱い

身代金は原則として支払わない。支払いを検討する例外的な状況では、グループCISOと構成会社責任者が
法務部門・法執行機関と協議して判断する。

> **カスタマイズ:** 身代金に関する方針は、経営層があらかじめ決めておくこと。

## 3. 外部連携・報告の補足

- 法執行機関には、身代金を要求するメッセージ、暗号化されたファイルの拡張子、攻撃者の連絡先を提供する([CSIRT-002](04-02-external-coordination.md))。
- データを持ち出された可能性がある場合は、[CSIRT-012](04-12-data-breach.md) を併用する。

## 4. 記録

[REC-001](../05-records-kpi/05-01-incident-record-format.md) の共通項目に加えて、次を記録する。

- 暗号化された範囲、バックアップの状態、復元に使ったバックアップの日時
- 身代金の要求額と、支払いについての判断の経緯
